# ✈️ SU-35 Notes — تطبيق ملاحظات الطيران (Flutter + Supabase)

تطبيق ملاحظات احترافي للطيارين والمهندسين، بأسلوب مبسّط يشبه Notion:
**مساحة عمل → دفاتر → صفحات → كتل محتوى**، مع صفحات متداخلة وحقول مخصصة لمجال الطيران
(نوع الطائرة، رقم التسجيل، فصل ATA، مطار ICAO، تاريخ الرحلة) وبحث نصي كامل.

> **حالة التسليم:** هذه النسخة تحتوي **المرحلة (أ) كاملة**: المصادقة + الدفاتر + الصفحات.
> المراحل (ب) المحرر، (ج) القوالب/الوسوم/البحث، (د) المزامنة دون اتصال — بانتظار موافقتك.

## 2) تشغيل المشروع خطوة بخطوة

### الخطوة 1 — إنشاء ملف `.env` (إلزامي قبل أي تشغيل)

ملف `.env` **مُدرَج ضمن assets** في `pubspec.yaml`، لذلك يجب إنشاؤه قبل `flutter run`:

```bash
cp .env.example .env
```

ثم افتحه واملأ القيمتين من لوحة Supabase: **Project Settings → API Keys**:

```dotenv
SUPABASE_URL=https://xxxxxxxxxxxxxxxx.supabase.co
SUPABASE_PUBLISHABLE_KEY=sb_publishable_xxxxxxxxxxxxxxxx
# ويُقبل أيضًا مفتاح anon القديم: eyJhbGciOi...
```

> 🔐 لا تُكتب المفاتيح في الكود إطلاقًا، وملف `.env` مستثنى من Git (`.gitignore`).
> الأمان الحقيقي للبيانات يأتي من سياسات **RLS** في `supabase/schema.sql` لا من إخفاء المفتاح.

### الخطوة 2 — تهيئة قاعدة البيانات في Supabase

1. أنشئ مشروعًا جديدًا على [supabase.com](https://supabase.com).
2. من **SQL Editor** نفّذ الملف كاملًا: [`supabase/schema.sql`](supabase/schema.sql)
   — ينشئ الجداول + الفهارس + البحث النصي (tsvector) + سياسات RLS + bucket المرفقات.
3. (اختياري لكن مُستحسن) نفّذ [`supabase/seed.sql`](supabase/seed.sql)
   — يمنح كل حساب بيانات بداية: دفتر الطيران + صفحة ترحيب + ٣ صفحات تجريبية
   (ملاحظة رحلة، قائمة ما قبل الطيران، تقرير عطل) + وسوم.
4. من **Authentication → Providers → Email**:
   - فعّل **Email** (مُفعَّل افتراضيًا).
   - للتجربة السريعة أوقف **Confirm email**، أو أبقِه مُفعَّلًا وسيُظهر التطبيق رسالة
     «تحقّق من بريدك» بعد التسجيل (الحالتان مدعومتان في الكود).
5. من **Authentication → URL Configuration** أضِف رابط العودة إن أردت استعادة كلمة المرور
   عبر رابط عميق لاحقًا (غير مطلوب للمرحلة أ).

### الخطوة 3 — توليد مجلدات المنصّات (مرة واحدة)

المستودع يحتوي كود Dart و`pubspec.yaml` فقط دون مجلدات `android/` و`ios/`.
ولّدها دون المساس بملفات المشروع:

```bash
# الطريقة الآمنة: توليدها في مجلد مؤقت ثم نسخ مجلدات المنصّات
cd /tmp && flutter create --org com.su35 --project-name su35_notes su35_platforms
cd - && cp -r /tmp/su35_platforms/android /tmp/su35_platforms/ios /tmp/su35_platforms/web .
```

أو ببساطة شغّل داخل جذر المشروع ثم استعد ملفات المشروع إن تغيّرت:

```bash
flutter create --org com.su35 --project-name su35_notes --platforms=android,ios,web .
git checkout -- pubspec.yaml lib/main.dart 2>/dev/null || true
```

### الخطوة 4 — التشغيل

```bash
flutter pub get
flutter gen-l10n     # يولّد lib/l10n/generated/app_localizations.dart (يحدث تلقائيًا أيضًا)
flutter run
```

`flutter run` / `flutter build` يولّدان الترجمات تلقائيًا لأن `l10n.yaml` + `generate: true` مُعدّان.

   │  └─ widgets/                      # ‏11 واجهة جاهزة: تحميل، خطأ، فارغ، حقول، منتقي أيقونة/لون…

      ├─ blocks/                      # المحرّر: كتل المحتوى + المرفقات + تصدير PDF

## 4) ما الذي يعمل في المرحلة (أ)؟

| الشاشة | ما تفعله |
|---|---|
| **الإقلاع (Splash)** | استعادة الجلسة المحفوظة وتحميل الملف الشخصي |
| **تسجيل الدخول** | Supabase Auth + رسائل خطأ مفهومة (بيانات خاطئة، بريد غير مؤكَّد، انقطاع شبكة) |
| **إنشاء حساب** | الاسم + الصفة المهنية (طيار/مهندس/طالب/مدرّب) + البريد + كلمة المرور، مع حالة «تحقّق من بريدك» |
| **نسيت كلمة المرور** | إرسال رابط الاستعادة + حالة نجاح |
| **الدفاتر (الرئيسية)** | قائمة الدفاتر مع عدد الصفحات وآخر تحديث، إنشاء/تعديل (أيقونة ولون ووصف ونوع طائرة)، تثبيت ⭐، أرشفة، حذف بتأكيد، سحب للتحديث، عرض المؤرشفة |
| **صفحات الدفتر** | شجرة **صفحات متداخلة** (صفحة داخل صفحة) بإزاحة بصرية، إنشاء صفحة/صفحة فرعية، تعديل، تثبيت، حذف |
| **تفاصيل الصفحة** | بيانات الطيران الكاملة (فصل ATA بالاسم، ICAO، التسجيل، التاريخ)، صفحات فرعية، محتوى الصفحة، وحقول قابلة للتعديل |
| **محرّر المحتوى (المرحلة ب)** | ١٠ أنواع كتل: نص غني (Quill) + عنوان + قائمة تحقّق + جدول + صورة + PDF + كود + اقتباس + تنبيه + فاصل، مع حفظ تلقائي وحفظ فوري وتصدير PDF |
| **الإعدادات** | وضع ليلي (نظام/فاتح/داكن)، اللغة (عربي/إنجليزي + RTL فوري)، بيانات الحساب، تعديل الملف الشخصي، تسجيل الخروج |

كل شاشة تعالج ثلاث حالات: **تحميل**، **خطأ** (مع زر إعادة محاولة)، و**فارغ** (مع دعوة لإجراء).

## 4ب) ما الذي يعمل في المرحلة (ب)؟

| **الخطوط** | خطوط Cairo مضمّنة في `assets/fonts/` إن وُجدت، وإلا تُنزَّل مرة واحدة من Google Fonts وتُخزَّن، وإلا تحذير واضح في الواجهة |

## 6) ملاحظات معمارية مهمة

- **الحالة (Riverpod 3):** `Provider` للاعتماديات، `Notifier` لحالة المصادقة (تحديثات فورية)،
  `AsyncNotifier` لقائمة الدفاتر مع تحديثات تفاؤلية وتراجع (rollback) عند فشل الشبكة،
  و`FutureProvider.family` لصفحات كل دفتر.
- **التوجيه (go_router 18):** حارس مصادقة (`redirect`) يمنع الوصول لشاشات الداخل بدون جلسة،
  ويحوّل المستخدم المسجَّل بعيدًا عن شاشات الدخول، مع `refreshListenable` يعيد التقييم عند كل تغيّر.
- **البحث العربي:** لا يوجد إعداد `arabic` في PostgreSQL، لذلك استُخدم `to_tsvector('simple', …)`
  مع فهارس `pg_trgm` للمطابقة الجزئية — يعمل جيدًا مع العربية والإنجليزية معًا.
- **الأمان:** كل جدول فيه `user_id` + سياسات RLS أربع (select/insert/update/delete)،
  وسياسات `pages`/`blocks`/`page_tags` تتحقّق أيضًا من ملكية الأب (الدفتر/الصفحة)،
  وbucket المرفقات خاص بمسار `{user_id}/{page_id}/{file}`.
- **الصفحات المتداخلة:** تُخزَّن مسطّحة (`parent_page_id`) ويُبنى الشجرة في Dart عبر `PageTree`
  مع كشف الحلقات، ويوجد مُشغّل في قاعدة البيانات يمنع الحلقات اختلاف الدفاتر.
- **المحرّر (المرحلة ب):** حالة المحرّر قصيرة العمر ومملوكة للشاشة (`BlockEditorController`
  كـ `ChangeNotifier`)، وكل وصول لقاعدة البيانات يبقى في طبقة `data`؛ هذا يمنع إعادة بناء
  الشاشة مع كل ضغطة زر ويحفظ التركيز داخل محرّر النص الغني.
- **المزامنة دون اتصال:** في المرحلة (د) تُضاف طبقة Drift محلية بين الواجهة و`data` دون تغيير الشاشات.

## 7) حلّ المشاكل الشائعة

| المشكلة | الحل |
|---|---|
| شاشة «تعذّر تشغيل التطبيق» | ملف `.env` غير موجود أو قيمه فارغة/غير صحيحة — تأكّد من `SUPABASE_URL` و`SUPABASE_PUBLISHABLE_KEY` |
| `Error: unable to find asset .env` عند البناء | نفّذ `cp .env.example .env` ثم `flutter pub get` |
| الدخول ينجح لكن الشاشة تبقى فارغة | نفّذ `supabase/schema.sql` بالكامل (خاصة مُشغّل `handle_new_user` وسياسات RLS) |
| `new row violates row-level security policy` | الجداول مفعّل عليها RLS بدون سياسات — أعد تنفيذ القسم (6) من `schema.sql` |
| ظهور `lib/l10n/generated/...` مفقود في المحرر | نفّذ `flutter gen-l10n` (أو `flutter run` مرة واحدة) |
| رسالة «تحقّق من بريدك» | أوقف Confirm email من Authentication → Providers → Email، أو أكّد البريد يدويًا |
| المحرّر يُظهر خطأ تحميل الكتل | لم يُنفَّذ `supabase/schema.sql` (جدول `blocks` + سياسات RLS) — نفّذه كاملًا ثم أعد المحاولة |
| فشل رفع صورة/PDF | تحقّق من تنفيذ قسم Storage في `schema.sql` (bucket `attachments` + سياساته) ومن أن حجم الملف < 50 ميجابايت |
| العربية لا تظهر في PDF | ضع `Cairo-Regular.ttf` و`Cairo-Bold.ttf` في `assets/fonts/` (راجع `assets/fonts/README.txt`) أو اتصل بالإنترنت مرة واحدة |
| الكاميرا/الصور لا تعمل على iOS | أضف `NSPhotoLibraryUsageDescription` و`NSCameraUsageDescription` إلى `ios/Runner/Info.plist` |
