# محرّر الكتل وتصدير PDF — مرجع المرحلة (ب)

> هذا الملف يشرح **كيف يعمل محرّر المحتوى** في تطبيق SU-35 Notes: نموذج الكتل،
> صيغة كل نوع في قاعدة البيانات، المرفقات في Storage، الحفظ التلقائي، وتصدير PDF.

---

## 1) نموذج المحتوى

الصفحة (`pages`) تحتوي **كتلًا** مرتبة (`blocks.sort_order`)، وكل كتلة سطر واحد
من نوع واحد. الأنواع العشرة مدعومة كاملة في المرحلة (ب):

| النوع (`type`) | الشكل في `blocks.content` (JSONB) | كيف يُحرَّر في الواجهة |
|---|---|---|
| `text` | `{"delta": [...], "text": "نص مسطّح"}` | محرّر غني (flutter_quill) مع شريط أدوات سفلي |
| `heading` | `{"text": "العنوان", "level": 1}` | حقل نص + زر تحدّد المستوى 1/2/3 |
| `checklist` | `{"items": [{"id","text","checked"}]}` | بنود بعلامة إنجاز + شريط تقدّم |
| `table` | `{"columns": ["عنوان"], "rows": [["خلية"]]}` | شبكة قابلة للتحرير + إضافة/حذف صفوف وأعمدة |
| `image` | `{"storage_path","file_name","mime_type","size_bytes","caption","attachment_id","width","height"}` | اختيار من المعرض/الكاميرا/الملفات + تعليق |
| `pdf` | نفس حقول الصورة مع `kind = 'pdf'` | اختيار ملف PDF + فتحه + تعليق |
| `code` | `{"language": "sql", "code": "..."}` | حقل اللغة + حقل كود بخط ثابت العرض |
| `quote` | `{"text": "..."}` | حقل نص مائل بحدّ جانبي |
| `callout` | `{"title","text","tone":"info\|warning\|danger"}` | عنوان + نص + اختيار النبرة (لون وأيقونة) |
| `divider` | `{}` | فاصل أفقي (لا محتوى) |

**مهم:** `content.text` في كتلة `text` يُخزَّن أيضًا في `pages.content_text` عبر مُشغّل
قاعدة البيانات `refresh_page_content_text` (يستخدم دالة `block_plain_text`) — لذلك
البحث النصي الكامل (المرحلة ج) يجد داخل كل الكتل بلا استثناء.

## 2) طبقات الكود

```
lib/features/blocks/
├─ domain/
│  ├─ block.dart            # NoteBlock + BlockType + قراءة/كتابة صفوف Supabase
│  ├─ block_content.dart    # نموذج محتوى كل نوع (Delta/بنود/جدول/وسائط/كود/اقتباس/تنبيه)
│  └─ attachment.dart       # Attachment + AttachmentKind (image/pdf/other)
├─ data/
│  ├─ block_repository.dart        # CRUD الكتل + تبديل ترتيب كتلتين
│  └─ attachment_repository.dart   # رفع/توقيع رابط/تنزيل/حذف المرفقات من Storage
├─ application/
│  ├─ blocks_providers.dart        # مزوّدات Riverpod (كتل الصفحة + المستودعات)
│  ├─ block_editor_controller.dart # عقل المحرّر: تعديل محلي فوري + حفظ مؤجَّل + تراجع
│  └─ rich_text_registry.dart      # سجلّ محرّرات Quill لربط شريط الأدوات بالكتلة النشطة
├─ presentation/
│  ├─ screens/block_editor_screen.dart
│  └─ widgets/              # إطار الكتلة، ورقة الأنواع، حقول كل نوع، شريط الحالة
└─ export/
   ├─ pdf_export_service.dart  # بناء ملف PDF من الصفحة + كتلها
   └─ pdf_export_sheet.dart    # واجهة التصدير: مشاركة/طباعة + تحذير الخطوط
```

**تدفّق الحفظ (مهم):**

1. الكتابة في أي كتلة → تحديث فوري في الذاكرة (`BlockEditorController.updateContent`).
2. بعد توقّف الكتابة (900 مللي ثانية) → `flush()` يحفظ الكتل المعلّقة فقط في Supabase.
3. أي فشل شبكة → تبقى الكتل في قائمة الانتظار، تظهر حالة **«فشل الحفظ — اضغط لإعادة المحاولة»**
   في شريط الحالة، ويُعاد الحفظ تلقائيًا عند المحاولة التالية أو عند إغلاق الشاشة
   (حفظ صامت في الخلفية) أو عند نقل التطبيق للخلفية (`AppLifecycleListener`).
4. الترتيب: الإضافة تُحسب بمنتصف المسافة بين الجارتين (لا إعادة ترقيم كامل)،
   والنقل لأعلى/أسفل يبدّل `sort_order` للكتلتين مع تراجع تلقائي عند الفشل.

## 3) المرفقات في Supabase Storage

- الـ bucket: `attachments` (خاص/private) — يُنشأ في `supabase/schema.sql`.
- المسار: `<user_id>/<page_id>/<uuid>.<ext>` (سياسات RLS تمنع أي مستخدم من رؤية ملفات غيره).
- الأنواع المسموحة: `image/jpeg`, `image/png`, `image/webp`, `image/heic`, `image/heif`, `application/pdf`.
- الحد الأقصى: **50 ميجابايت** لكل ملف (مضبوط في الـ bucket وفي التطبيق معًا).
- العرض: الصور تُعرض عبر **رابط موقّع مؤقت** (`createSignedUrl` لمدة ساعة)،
  وملفات PDF تُفتح في تطبيق خارجي عبر `url_launcher`.
- عند استبدال ملف أو حذفه: يُحذف الملف القديم من التخزين ومن جدول `attachments`
  (مع تجاهل فشل حذف الملف غير الموجود).

## 4) تصدير PDF

`PdfExportService` يبني ملف A4 (متعدّد الصفحات) يحتوي:

- ترويسة: اسم التطبيق + الدفتر + تاريخ التصدير (بالعربية/الإنجليزية حسب لغة الواجهة).
- عنوان الصفحة + جدول البيانات الجوية (نوع الطائرة، التسجيل، فصل ATA بالاسم، ICAO، التاريخ).
- الملخّص ثم كل الكتل: العناوين، النص الغني (مع **عريض/مائل/تحته خط/يتوسطه خط/روابط/ألوان**)،
  القوائم، قوائم التحقّق (مربّع مرسوم بدل رمز ✓ لتفادي مشاكل الخطوط)، الجداول،
  الصور (تُنزَّل من Storage وتُدرج داخل الملف)، ملفات PDF المرتبطة (تُذكر بالاسم والمسار)،
  الكود (بخط ثابت العرض)، الاقتباس، والتنبيهات (بألوان النبرة).
- ترقيم الصفحات في التذييل.

### الخطوط العربية في PDF

الخطوط تُطلب بالترتيب التالي، وأول نجاح يُستخدم:

1. **خطوط مضمّنة في التطبيق** (الأسرع وبدون إنترنت): ضع `Cairo-Regular.ttf` و `Cairo-Bold.ttf`
   في `assets/fonts/` — راجع `assets/fonts/README.txt` (ترخيص SIL OFL).
2. **تنزيل تلقائي** لخط Cairo من Google Fonts (`PdfGoogleFonts.cairoRegular/cairoBold`) —
   يحتاج إنترنت مرة واحدة ثم يُخزَّن مؤقتًا.
3. **خطوط PDF الافتراضية** (لاتينية) مع ظهور تحذير واضح في واجهة التصدير أن العربية
   قد لا تظهر كاملة.

> كيف نعرف نوع الخط المتاح؟ `PdfExportResult.fontsReady` — واجهة التصدير تعرض التحذير
> عندما تكون قيمته `false`.

### المشاركة والطباعة

- `Printing.sharePdf` → مشاركة الملف (واتساب، بريد، حفظ في الملفات…).
- `Printing.layoutPdf` → معاينة الطباعة أو الطباعة الفعلية.
- اسم الملف المقترح: `<عنوان الصفحة>_<YYYY-MM-DD>.pdf`.

## 5) سلوك واجهة المحرّر

- **شريط الحالة** أعلى الشاشة: غير محفوظ / جارٍ الحفظ / «حُفظ 14:32» / فشل الحفظ (قابل للنقر للمحاولة).
- **قائمة كل كتلة** (⋮): إضافة كتلة بعدها، تحريك لأعلى/أسفل، تغيير النوع (بتأكيد لأن المحتوى سيُستبدل)، حذف (بتأكيد).
- **زر «إضافة كتلة»** أسفل الشاشة يفتح ورقة الأنواع مقسّمة إلى: أساسية / مرفقات / متقدّمة.
- **شريط أدوات النص الغني** يظهر أسفل الشاشة فقط حين تكون هناك كتلة نصية مُركَّز عليها،
  ويتحكّم بها وحدها (سجلّ `RichTextRegistry`).
- كل شاشة تعالج ثلاث حالات: تحميل، خطأ (مع إعادة محاولة)، وفراغ (مع دعوة لإضافة أول كتلة).

## 6) ما يحتاج إنشاءً على جهازك

| العنصر | السبب | أين |
|---|---|---|
| `assets/fonts/Cairo-*.ttf` | تصدير PDF بالعربية بدون إنترنت | `assets/fonts/README.txt` |
| مفاتيح iOS للصور/الكاميرا | `image_picker` | `ios/Runner/Info.plist`: `NSPhotoLibraryUsageDescription` و `NSCameraUsageDescription` |
| لا شيء على Android | منتقي الصور الحديث + Storage SDK | — |
| تنفيذ `supabase/schema.sql` | جدولا `blocks` و`attachments` + bucket + سياسات RLS | `README.md` → الخطوة 2 |

إن لم تُنفَّذ `schema.sql` فسيفشل المحرّر عند التحميل بخطأ RLS أو «جدول غير موجود» —
وهذا مقصود حتى لا تُكتب بيانات في جداول ناقصة.
